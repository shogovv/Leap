# Leap 開発哲学(プロダクト・操作設計)

Leap は「新しいタブを開いた瞬間から、キーボードだけで行きたい場所に着く」ための拡張機能。
機能を足すときは、まず以下の原則に照らして判断する。迷ったら「従来のワークフローを壊していないか」「手が止まらないか」を優先する。

## 1. キーボードファースト、フォーカスは常に入力欄

- フォーカスは常に `#queryInput` にある。ページ内のどこをクリックしても入力欄に戻す。
- 「ボタンにフォーカスを移して Enter」のような一般的な Tab 移動は採用しない。ボタン類にはショートカットで直接アクセスさせる(例: Web検索ボタン = `Ctrl+Enter` と同じアクション)。
- `Tab` / `Shift+Tab` も DOM フォーカス移動ではなく、選択移動として使う(`Ctrl+P` / `Ctrl+N` と同じ)。

## 2. 選択移動は「一貫性」を優先する

- `↑↓←→`、`Ctrl+P/N`、`Tab/Shift+Tab` はすべて「結果リストの選択移動」。入力欄内のテキストカーソル移動は**諦める**。
  - 検討済み・却下: 「カーソルが先頭/末尾のときだけ ←→ で選択移動」。実際に使うと大半の場面でテキストカーソル移動に見えてしまい、不便だった。一貫している方が体感が良い。
- 矢印キーは DOM 順ではなく実際の描画位置(`getBoundingClientRect`)から最寄りの隣接要素を探す。グリッド/リストの列数に依存させない。
- `Ctrl+文字` でのジャンプ用ヒント文字(`HINT_POOL`)は、macOS/Chrome の Emacs 風テキスト編集キー(a,b,d,e,f,h,k,n,o,p,t,y,m)を避けて選ぶ。

## 3. Enter の意味は「選択の有無」で決まる。推測ヒューリスティクスは入れない

- 絞り込み中は常に先頭のヒットが自動選択される(今まで通り)。**入力のたびに選択を「なし」にリセットする案は却下**。数文字打って Enter でトップ候補を開く、が Leap の一番の強みだから。
- `Enter`:一致あり → 選択中の項目を開く / 一致 0 件 → Web検索へフォールバック。
- `Ctrl+Enter`(または Web検索ボタン):一致の有無に関わらず常に Web検索。
- **URL をペーストしたら、検索を経由せず即座にそのタブで遷移**。オムニバーでの「Cmd+T → Cmd+V → Enter」の筋肉記憶を壊さないための設計。
- 0 件になったら、Web検索エリアが「選択状態」(項目の選択枠と同じ見た目)になり、`Enter` 表記も追加表示される。「今 Enter を押すと何が起きるか」が見た目で分かること。

## 4. レイアウトと視線の流れ

- 検索欄は**上**に置く(視線の起点 → コンテンツ、の流れ)。ヘッダー直下・左寄せ・コンパクト幅・`position: sticky`。横長バーは却下。
- Web検索は入力欄とは**別エリア**として、ラベル付きで独立させる。ショートカット(`Ctrl+Enter`)は常時表示し、ホバーしないと分からない状態にしない。
- ヘッダー・検索行・コンテンツは同じ `max-width: 1200px` の中央カラムに揃える(ワイド画面でズレない)。
- 見た目は「紙の文具」+「時間帯で変わるムード」。派手な演出より、常時使う道具としての落ち着きを優先する。

## 5. 言葉づかい

- 専門用語を避ける。「AND」ではなく「言葉を続けてさらに絞り込む / 空白で区切る」。
- キー表記は記号(⌃)ではなく `Ctrl+P` のように綴る。
- プレースホルダーは「検索」ではなく、軽い誘い水(「なんでも入力」「Type something」等)。日英各 10 種からランダム表示。
  - 見た目は控えめに:細字・入力文字より小さく(13.5px)・`--sub` を 40% まで薄くして、存在感を出さない(濃い太字は「鬱陶しい」と却下)。バー内で文字の**見た目**が縦中央に揃っていること(要素ボックスの中心が合っているだけでは不十分。詳細は engineering-notes.md)。
- 0件のときの空状態は「無い」だけで終わらせず、次の一手(Web検索)を促す。1行目は日英各10種からランダム(検索が続く間は固定してちらつかせない)、2行目は `Enter で「入力した文字」をWeb検索`(長い入力は24文字で省略、入力が空なら出さない)。
- 名前・機能の説明は、響きだけでなく機能と繋がっていること(Leap = 一足飛びに目的地へ)。

## 6. 多言語(ja / en)

- すべての文言は `i18n.js` の `MESSAGES` に ja/en 両方を持つ。UI の直書き文字列を増やさない。
- 挨拶文は各ムード ja/en 100 個ずつ。英語は直訳ではなく、そのムードの温度感を英語として自然に書き下ろす。
- ユーザー自身のブックマークフォルダ名は翻訳しない。疑似セクション(ブックマークバー / 開いているタブ / 最近閉じたタブ)だけ `nameKey` で翻訳する。
- 言語切替は即時反映(UI・挨拶・プレースホルダー・日付ロケール)。

## 7. 信頼できる見た目・透明性

- README は誇張なし。機能、インストール手順、キーボード表、**権限とその理由**を正直に書く。権限を増やしたら理由も README に足す(例: `search` はWeb検索のため)。
- `manifest.json` の `description`(chrome://extensions に出る説明)は英語で、Chrome ウェブストアの上限 132 文字以内、現在の機能を正確に。機能を足したら実態とズレていないか見直す。
- 外部サーバーには一切通信しない、ということを崩さない(favicon も `favicon` 権限のローカル経路)。
- 設定パネルの「AIに使い方を教えてもらう」プロンプトは、まず GitHub リポジトリを読み込ませ、ユーザーのショートカット習熟度と新規タブでの行動をヒアリングしてから教えさせる構成にする。

## 8. サイト内検索(登録ショートカット)

Chrome の「サイト内検索」(`chrome://settings/searchEngines` のキーワード + `%s` テンプレート)は、拡張機能から呼び出す公開APIが存在しない(`chrome.search.query` は既定エンジン固定、`chrome.omnibox` は自前キーワードの新規登録のみ)。なので Leap 自身が同じ体験を持つ:

- **発動条件は「先頭トークンの完全一致 + スペース」のみ**。`Tab` は既存の選択移動(§1)と衝突するため採用しない。この一致は推測ヒューリスティクスではなく、Chrome自身のオムニバーキーワードと同じ厳密な仕組みなので、§3 の「推測ヒューリスティクスは入れない」に反しない。
- **発動中は Enter の意味が変わる**(§3 の原則に対する唯一の例外):選択の有無ではなく「サイト内検索を開く」になる。これは能動的な操作(登録済みショートカット + スペースを自分で打つ)を経て初めて入るモードであり、暗黙の推測ではないため一貫性を破らない。
- **`Ctrl+Enter` は発動中も常に「逃げ道」として機能する**(既定検索エンジンで、チップ抜きの残りの語句を検索)。却下案:発動中は Web検索ボタンを非表示/無効化する — 誤発動(ショートカットのつもりじゃない一文字)から戻れなくなるため却下。見た目だけ `opacity` を落として「今回の主役はこっちじゃない」と控えめにするに留める。
- **チップの見た目**:検索欄の手書き風 `Kalam` は使わない(§ engineering-notes.md のフォント混在バグ参照)。背景は白/`--card`、境色だけをそのエンジンの色にする(却下案:塗り背景。実際に試すと「危険を示す赤」に見えて用途と合わなかった)。テープと同じ `ACCENT_CYCLE` を使い、登録時に固定で1色割り当てる(他のエントリを消しても色が変わらないように)。
- **アイコンは絵文字を自由入力+候補ショートカット、または画像アップロード**。絵文字ピッカーを自作(検索可能な全絵文字データベース)するのはこの拡張の規模に対して過剰なので、OS標準の絵文字ピッカー(`Win+.` / `Ctrl+Cmd+Space`)にそのまま乗る入力欄+ よく使う候補の小さな一覧、という設計にした。
- **削除は確認なしで即時**。拡張全体に確認ダイアログの慣習がない(ブックマーク編集も `chrome://bookmarks/` に委ねている)ことに揃えた。
- **エクスポート/インポートはJSONファイル**。バックアップや他マシンへの移行、他の人との設定共有を想定。インポートは**ショートカット名(keyword)でマージ**する — 同じショートカットが既にあれば上書き更新、無ければ追加。「衝突したら全部エラーにする」より、バックアップの再インポートや設定の共有が実際に使える形になる。ここも確認なしで即時反映(上記の削除と同じ理由)。

## 9. やらないこと

- ビルド工程・フレームワーク・バンドラは入れない(素の HTML/CSS/JS、Manifest V3)。
- 入力のたびに選択をリセットする、Enter の挙動を曖昧なヒューリスティクスで変える、などの「賢そうだが予測しづらい」挙動。
- 全幅の横長検索バー、ホバー必須のショートカット表示。
